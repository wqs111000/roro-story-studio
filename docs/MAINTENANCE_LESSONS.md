# 代码审核与维护经验

更新：2026-09-06。依据 `b211bf5` 的代码审核整理；这是后续维护方法，不代表当前服务已部署该提交。故事制作规则另见 [制作经验](PRODUCTION_LESSONS.md)，使用入口见 [工作台流程](WORKBENCH_WORKFLOW.md)。

## 工作台加载不能改变数据职责

- 备选列表返回摘要，不包含完整页内容。打开详情仍需请求 `/api/studio/story-library/<id>`，显示正文、对白和实际朗读；不能为了减少请求直接拿摘要代替详情。
- 先清除上一本详情并显示加载状态。用请求序号或等效机制隔离响应：先点 A 再点 B，即使 A 最后返回，也不得覆盖 B；错误反馈同样受此约束。
- 首屏可以按标签分阶段加载，但“首次延迟加载”不应成为刷新函数的永久早退条件。备选加载失败时，手动刷新制作进度仍须可用。
- 写入成功与后台刷新成功是两个结果。服务确认保存后立即反馈；刷新失败应提示列表暂未同步，不要把已保存误报为保存失败或自动重复写入。
- 浏览器保留 CSRF 值不代表 PIN 会话仍有效。写前重新核对会话，服务端继续检查同源、CSRF 和权限；开发免 PIN 模式也不取消请求保护。

## Windows 派生缓存与 PDF

缩略图先写独立临时文件，再原子替换版本化目标。Windows 上另一请求可能已安装并打开同一版本目标，导致替换出现 `PermissionError`。当前实现仅在该目标文件已经存在时复用它，否则重新抛出错误，并清理本请求临时文件。

这项容错限于可重建、同版本的缩略图缓存，不适用于原始图片、审核记录或不可变 release。不得推广为吞掉所有权限错误；后续若出现损坏缓存，应增加可读性/内容校验和明确恢复路径。

PDF 排版变化需要同步更新 `PDF_LAYOUT_VERSION`，避免复用旧版派生 PDF；当前源码值为 7，结束页增加域名署名。发布资产仍不可原地覆盖。缓存版本或源码检查只能证明失效机制，页脚是否遮挡、字体是否缺失仍需实际生成并渲染验收。

## 回归与实际使用验收

从项目根目录执行：

```powershell
python -X utf8 -m unittest discover -s tests -q
node --test tests/test_workbench_detail.cjs
git diff --check
```

若 Node 测试隔离进程受环境限制，可使用 `node tests/test_workbench_detail.cjs` 执行同一测试文件，并在结果中注明运行方式；不能将启动失败写成通过。

`test_workbench_detail.cjs` 使用模拟页面节点验证按需取详情和乱序响应隔离，不覆盖真实 DOM、网络认证、HTML 转义或完整用户交互。源码字符串断言只能辅助检查，不足以证明按钮行为。

修改相关路径时按风险补测：列表故障后的手动刷新、保存成功但刷新失败、过期 PIN 会话、并发缩略图生成。网页实际验收再检查桌面/窄屏、连续打开两本详情及失败提示；会产生状态变化的测试使用隔离样例，不操作真实书籍。音频需试听，PDF 需渲染，部署需核对运行版本，各自单独留证。

## 审核、提交和发布的范围

开始时检查分支、远程、差异和未跟踪文件，区分通用代码、私人内容与运行缓存。`work/` 等临时目录不能仅因是脚本就进入 Git，更不能为“验证”而运行会批量改写故事或自动填写通过记录的脚本。结构完整、哈希匹配不等于实际看图和试听。

只暂存已审核的明确文件，检查暂存差异和敏感信息后再提交。私有仓库也不自动获准上传家庭资料。遇到冲突、分歧、权限或认证问题，保留现场；不要自动清理、覆盖或强推。

分别报告测试、提交、推送和运行部署结果。“更新文档”不自动授权推送、部署或故事上架。历史提交/测试数字只作为带日期的记录，不能作为当前状态。
