# NAS 在线内容同步方案

日期：2026-09-07。状态：首版协议与本地服务接入已实现，未部署、未连接 NAS 现场验收。

## 目标和审查范围

桌面端负责制作、审核和上架；NAS 保存可离线播放的展示副本。用户在 NAS 书架点击“检查更新”，即可同步新增、修改和下架内容；不需要终端、不重复传整库、不因内容更新重启服务。

本轮审查覆盖项目架构、候选发布、书架状态、播放资源与缓存、图鉴、PDF、桌面/NAS Compose、展示包和候选同步脚本及相关测试入口。属于代码与设计审查，不等于所有故事的视觉验收、全项目安全审计或 NAS 现场验收。当前本地回归已覆盖协议基础行为；未连接 NAS 验证活动配置。现有无关工作区修改保持原状。

## 已发现的缺口与修正

| 现状/先前提议 | 缺口 | 最终处理 |
|---|---|---|
| `release_id`、`package_digest` 已存在 | 内容版本不记录上下架状态；同一版本可以重新上架 | 内容版本与书架快照版本分开 |
| `/api/stories` 是展示目录 | `_approved_stories` 会跳过缺图/缺音频等条目，且不提供完整同步版本字段 | 独立发布索引；异常不解释为删除 |
| “索引里没有就删除” | 网络失败、损坏或读到不完整目录可能误删 | 使用显式下架/删除记录；不明缺失报异常并保持副本 |
| 下架状态位于运行时文件 | 当前展示包不复制运行时文件；单独同步 release 看不到下架 | 仅导出规范化公开状态，不复制整个 runtime |
| `_approved_story_detail` 先生成摘要再读取当前目录 | 切换期间可能新正文配旧音频 | 每次请求固定同一份索引和 release，所有派生数据共同使用 |
| 目录缓存为 8 秒，网页加载时拉取一次 | 更新完成不一定立即显示 | 以活动快照版本驱动缓存失效；完成后重新加载书架 |
| 图鉴图片缓存一小时 | 原路径覆盖可能继续显示旧图 | 图鉴版本化，资源采用不可变版本/摘要 URL |
| NAS 数据挂载只读，所有 POST 被禁 | 页面加按钮本身无法执行同步 | 明确增加有限同步能力与目录写权限，制作审核仍不可用 |
| `prepare_release.verify` 要求精确文件集合且每书唯一 release | 在线暂存和旧版保留会违反旧包校验 | 区分首次快照包校验与在线活动快照校验 |
| 多本书分别改 `current.json` | 无法原子提交书架、图鉴、排序和下架状态 | NAS 用一个活动目录快照作为读取入口 |
| 原有通用静态文件回退 | 不能把暂存、凭据放进可浏览目录；隐藏书架不等于禁止旧链接 | 暂存/状态放在静态根外；资源下载仅开放展示清单中的资产 |

依据：`service/review_store.py` 的发布、状态和目录解析；`service/story_server.py` 的目录、详情、缓存、图鉴、PDF与静态路由；`scripts/nas/prepare_release.py`；`deploy/nas/compose.yaml`。已有不可变 release 和音轨时间轴可以复用，无需改变创作流程或重审既有绘本。

## 用户使用方式

1. 首次配置 NAS 所连接的桌面服务地址并完成设备配对；保存连接配置。
2. NAS 书架显示“检查更新”和最近同步状态，家庭局域网模式无需每次输入 PIN。
3. 点击后显示“新增 N 本、更新 N 本、移除 N 本”，有变化时点击“同步更新”；没有变化显示“已是最新”。
4. 下载和校验在后台运行，页面显示进度；关闭网页不取消任务，再次打开可查看任务状态。
5. 完成后自动刷新书架；正在播放的页面不强制重载。
6. 提供“自动同步”开关，默认关闭；开启后 NAS 每 5 分钟检查并同步，桌面离线时退避重试，恢复在线后自动追上。

“移除”表示从 NAS 书架下架，不删除桌面内容。已授权的自动同步包含桌面明确下架的传播。桌面端可以后续显示 NAS 最近成功同步时间；首版无需桌面主动通知，轮询不会漏掉离线期间的变化。

## 版本与发布索引

- `source_id`：持久桌面库身份，防止配置错误或库被重建后把另一个库当作当前库。变化要求重新配对。
- `story_id`：绘本固定身份。
- `release_id`：不可变内容版本；比较相等与否，不依赖名称排序，也允许桌面明确切回已发布旧版。
- `package_digest`：沿用发布包摘要；同版本不同摘要视为冲突。它校验一致性，不单独证明来源可信。
- `catalog_revision`：单调递增的发布索引序号，覆盖新增、修改、下架、恢复、图鉴和展示元数据变化。
- `catalog_digest`：该完整索引的摘要，也作为条件请求的 ETag；序号相同摘要不同拒绝接受。
- `characters_revision`：图鉴版本；独立于单本绘本版本。

发布索引包含协议版本、源身份、完整快照标识、版本号、绘本状态、release/摘要、资产 manifest 摘要和大小、图鉴及排序元数据。不包含草稿、制作队列、PIN、审核日志、家庭参考照片。发布清单内必要的批准来源字段保留其真实身份验证模式。

桌面端仅在“通过并上架”或上下架成功后更新索引。索引应持久保存并原子提交；发布与索引之间的中断通过启动/检查时对账恢复。构建索引时锁定一致的发布状态；已上架内容校验失败则报告索引不可用，不能静默排除该书后生成成功快照。

下架使用持久 `unpublished` 记录；未来若增加正式删除操作，再输出 `deleted` 记录。手工移走文件不代表业务删除。长期离线 NAS 仍能通过完整快照读取下架记录。空书架仅在明确有效的完整索引和下架记录下被接受；请求异常或空响应绝不清空 NAS。

| 对比结果 | 行为 |
|---|---|
| 新的已上架 story | 下载该书所需资产 |
| 同 release、同摘要 | 跳过完好本地文件 |
| 不同 release | 下载/复用新版本资产，校验后切换 |
| 同 release、不同摘要 | 报冲突，保持当前快照 |
| 明确 unpublished/deleted | 新活动快照移除该条目 |
| 同版重新 published | 恢复展示，文件仍完整则不重传 |
| 仅图鉴/排序变化 | 仅下载对应元数据和资源 |
| 本地文件缺失或损坏 | 标记需要修复并重取，不能仅因版本相同跳过 |
| 来源不匹配、索引不完整、未知条目消失 | 不应用，显示异常 |

本地保存验证结果和文件大小/修改信息，普通检查无需每次重算全部大音频哈希；安装与修复时完整校验，并提供内容完整性检查以发现同大小的静默损坏。

## 实现结构

首版保留一个 NAS 应用容器，在应用内加入独立后台同步工作模块和单任务队列。不新增消息队列、数据库服务或必须管理的第二个容器。同步模块与展示路由职责分离，后续有需要可拆出进程。

NAS 网页调用本机同步控制接口，NAS 后端再向固定桌面源下载，浏览器不直接下载整本或保存连接凭据。同步仅能安装桌面已发布内容；改源地址、配对及策略配置属于设备设置。按钮不接受任意下载 URL 或本地路径。

服务端采用同源请求校验、CSRF 防护、设备凭据、单任务锁和短冷却，重复点击返回同一个任务。家庭局域网模式公开展示页可触发固定源同步，不强制管理员登录；将来开放公网再配置统一访问控制。HTTP 局域网是本方案运行前提，设备凭据不替代传输加密。

拟增加的接口（实现时可调整命名）：

- 桌面：只读 `/api/sync/catalog`（支持 ETag）、版本固定的 manifest/资产下载、NAS 同步成功回执。
- NAS：读取同步状态、检查更新、开始同步；检查结果绑定目标快照，源变化时重新检查，避免实际移除项超出页面显示。

下载端限制来源、重定向、相对路径、文件数量和大小；依据 manifest 白名单接收文件，校验 SHA-256。资产采用逐文件传输，复用本地已验证且摘要相同的文件；未变化文件无需跨网重传。首版支持文件粒度重试/恢复，不要求 WAV 内部块差分。

NAS 的代码目录继续只读；内容存储、同步状态/暂存和 PDF 缓存需要可写。该调整意味着现有 `display-only` 的“所有写入都禁用”应改为“禁止创作审核，允许受限内容同步”，并更新说明和测试；不能宣称原先只读配置无需变化。

## 在线提交、恢复和播放

NAS 使用稳定挂载的内容根目录，新增一个本地活动索引入口。活动索引引用不可变 release、图鉴版本和排序元数据。桌面的 `current.json` 仍是创作端发布指针；NAS 在线模式以活动索引为准，避免两个独立可写权威。既有 current 文件用于初始导入，切换后不混合回退。

同步顺序：获取并验证目标快照 → 比较版本 → 检查磁盘空间 → 下载到静态服务根外的暂存目录 → 校验资产 → 安装不可变目录 → 复核目标快照仍有效 → 原子替换活动索引 → 使缓存失效 → 记录成功回执。

整个批次准备完毕才切换一次活动索引。某本下载失败则旧快照继续服务；已下载且校验完的文件留待重试。大批更新期间，页面明确显示仍在使用旧书架。源在过程中改变则重新对账，已经下载的相同资产复用，不提交过期的移除列表。

活动索引临时文件与正式文件放在 NAS 同一文件系统；提交需要落盘和可恢复记录。启动时核对活动索引及已安装资源，不依赖网页会话恢复任务。不得通过重命名/替换 Docker 挂载根目录来模拟切换。

每个目录/详情请求固定读取一份活动索引；图片、音轨和时间轴使用同一 release 的 URL。更新替换的旧版本暂留以支持已打开播放器，默认保留至少 7 天；下架后立即禁止新开播放/下载，已经打开的页面和缓存允许完成本次播放。此处不是即时安全撤回功能。

旧版清理仅处理 NAS 同步器拥有且已无活动引用的资源，单独执行并记录；首版不自动物理清理，页面可显示待清理空间。将来启用自动清理时需要播放占用/保留期判断，不能承诺无限期打开的旧页面永不中断。源端旧 release 不受 NAS 清理影响。

PDF 继续按 release 和布局版本本地生成/缓存，不同步旧缓存。所有图片/音轨选择按当前 manifest，兼容性回退不能把额外历史文件带进新展示版本。图鉴与资源 URL 同样版本化。

## 上线迁移与范围

1. 先实现协议、桌面索引和 NAS 同步模块及网页入口，使用隔离测试数据验证。
2. 现场只读核对 NAS 当前项目目录、实际 Compose 文件、镜像、UID/GID、桌面可访问地址和磁盘空间。源码配置及旧部署记录不能代替现场状态。
3. 首次启用需要一次应用代码/Compose 升级和重启。对现有 NAS 内容逐项验证后生成初始活动索引，复用已有文件；不重新审核或改写桌面 release。保留旧配置和数据用于迁移回退。
4. 验证新内容、修改、下架、恢复及离线播放。之后日常内容同步在线完成，不重启容器、不导入镜像。

首次安装/灾难恢复保留完整展示包工具；旧 `preparation.json` 只证明首次快照，后续以活动索引和同步记录验证。代码升级与内容同步分开；只修改网页静态文件通常刷新即可，Python 代码升级需重启，运行依赖变化才重建镜像。

实施范围包含手动检查、同步、自动同步开关、状态显示、增删改/恢复、图鉴、缓存一致性和故障恢复。不含公网发布、云服务、多源合并、双向创作同步、软件自更新、自动清理或桌面推送通知。

## 验收条件

- 首次同步与已有数据迁移都能完整播放并下载 PDF，全部音色时间轴正确。
- 未变化检查不传媒体；新增一本仅传该书及必要元数据；修改只重传摘要变化文件。
- 同版下架、恢复、图鉴独立更新都能生效；明确空库可处理，异常空响应不移除内容。
- 下载断网、校验失败、空间不足、进程重启时保留可用旧快照，重试复用已验证资产。
- 反复点击、自动任务与手动任务同时触发时只有一个写入任务。
- 更新中正在播放的音频及后续 Range 请求可继续；详情不会混用两个 release。
- 同版本摘要冲突、陌生 source、旧目录序号、非法路径均不提交。
- 桌面在检查后或下载中改变书架时重新对账，页面状态真实反映应用结果。
- NAS 制作审核接口继续不可用；暂存和凭据不可通过静态路由读取。
- 现有发布审核、工作台、书架、图鉴、PDF 和 NAS 部署相关回归通过，再进行两端实际网页验收。

当前代码已提供目录、资源下载、同步状态、手动/自动同步入口和受限展示端写入；仍需在隔离测试数据和实际 NAS 上完成端到端验收后，才能宣布部署完成。本文件不代表已向 NAS 写入家庭内容，也不代表已经启用自动同步。
