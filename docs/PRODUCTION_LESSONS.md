# 绘本制作经验与复用规则

整理日期：2026-09-06。来自已有制作规范、工作台复盘与当前代码核对。以下是后续制作规则，不是本次重新验收既有绘本的结论。

| 已遇到的问题 | 形成的做法 | 落点 |
| --- | --- | --- |
| 视觉计划和原分镜各写一份，容易相互矛盾 | 扩展原 `storyboard.json`，提示词从中派生 | `visual_plan.py`、分镜 Schema |
| 只写“参考图路径”却没有附图，角色仍漂移 | 使用最新已批准图鉴；每次实际附参考图 | 角色注册表、制作技能 |
| 后页不断参考未验收的前页，错误累积 | 先接受代表页，再锁定本故事尺度与场景；不把未经审核的图片串成唯一参考 | `visual_production` |
| 把地点、昼夜和剧情变化误判为连续性错误 | 场景锚点固定未变化的关系；每页写清 `state` 和 `allowed_changes` | 分镜、视觉审核 |
| 用其他故事的像素比例硬套当前故事 | 以本故事接受页为尺度锚点，对相似景深和姿态比较 | `scale_relationship` |
| 插图底部出现浅色条或空白字幕区 | 母版全画幅，文字移到播放器/PDF 排版层 | 提示词、联系表检查 |
| 小道具不符就反复重画，人物反而变差 | 合格画面的非关键差异用 `text-adapt`，保留主题、因果、安全和关键选择 | 五份文字来源、受影响页音频 |
| 异常手指、错角色被文字解释掩盖 | 此类属于 `repair`，不得改故事来迁就 | `visual-review.json` |
| 近似构图反复生成、全书反复上传看图 | 一次整本联系表；仅标记页看原图；初稿后默认一次定向返修 | 次数、具名问题、第二次返修理由 |
| 低清草图通过后重新生高清，细节又漂移 | 合格图尽量保留并局部修复；重新生成的图仍是新候选，不能继承视觉通过 | 图像哈希及复核记录 |
| 图鉴形态名、情绪标签或生产说明混入故事 | 儿童只听故事；制作信息留在分镜和内部证据 | 正文、旁白与审核清单 |
| 音频只有台词，听众不知道是谁说的 | 对话加入自然 `speech_cue`，无指定时用“角色名说” | 旁白合成与 alignment |
| 多声音按总时长比例翻页，逐页越播越偏 | 每声音独立封面标题、页片段和真实时间轴；换声音保留页内进度 | 音频缓存、`.sync.json`、播放器 |
| 文字只改一处，字幕、朗读与分镜分离 | 同步 `story.json`、`story.md`、`narration.json`、`storyboard.json`、`review.md` | 文本适配与音频复核 |
| 文件齐全就被脚本标成内审通过 | `--inspect` 只选材和算摘要，打包必须读取真实独立证据 | 候选准备脚本 |
| 相同图片集合却可能审核错页 | 封面固定页 0，每页图像按页码逐一匹配候选，不只比较文件集合 | 本次新增页码绑定校验与回归 |
| 旧批准字段、旧音轨或重复版本影响当前候选 | 按 manifest 指定资产，决定绑定版本和摘要，release 不可变 | `review_store.py` |
| 点击加入制作后误以为系统已开始生图 | 明确网页只保存制作清单，由创作客户端继续 | 工作台流程说明 |
| 历史测试数量、书籍数量和容器状态写成永久事实 | 长期文档写机制；阶段记录写日期、范围与验证结果 | 维护交接、阶段复盘 |

## 2026-09-06 补充：制作前置条件和证据恢复

- 新登场动物也必须在 `visual_production.characters` 中有对应绑定及实际复核过的参考，不能只在 shot 里写名字。复用已批准角色时使用精确身份和参考；明确等待家长批准的角色仍须等待，不得用内部检查替代批准。
- 先补全封面 `cover` 和角色绑定，再编译、生成并检查代表页；将真实锚点路径及哈希写回分镜后，编译依赖它的封面和后续页。批量生成前检查所有待生成页，不能要求尚未生成的锚点预先存在，也不能跳过失败页的编译器。
- `visual-review.json` 的图片路径从仓库根目录解析，封面为页 0，每个分镜页恰好一行。修路径后核对真实文件与哈希；修改输入摘要后检查受影响关系，不得顺便把未审页面写成通过。
- 封面标题由页 0 音频段朗读，不能重复写入第 1 页。对白在旁白和角色段中只出现一次，互动提示必须成为实际口播段，文本与故事字段一致。文字适配后同步五份文字来源，再处理受影响页的所有提供音色。
- 临时脚本可以辅助校验或整理字段，不能以文件存在、页数齐全或自动填入 `passed` 代替实际视觉和音频审核。无法恢复检查证据时，保留未完成状态。

这些规则已纳入现有故事技能，不新增平行制作流程。工作台加载与代码提交经验见 [维护经验](MAINTENANCE_LESSONS.md)。

## 每本完成后记录什么

在该书 `review.md` 中补充页数、首轮接受页数、各页最终 verdict、返修次数和具名缺陷、文字适配内容、受影响音色/页、制作耗时及外部等待。`visual-review.json` 保留图像和输入摘要的机器绑定。样张已检查的观察可以复用，不重新分析未变化图片。

区分初稿生成次数和后续返修次数。默认最多三次生成（初稿、首次返修、具备具体理由的第二次返修）；超出时重新设计构图或暂停该页。时间或服务中断应记为未完成，不写“已生成”或“已通过”。

这些记录用于下一本调整构图与参考策略；没有对照样本和实际整本验收前，不宣称规则已经降低某个比例的成本或提升某个比例的一致性。

## 后续仍需留意

- 当前输入摘要包含全视觉计划，影响范围偏保守。更新时需要判断受影响关系，不能为省事直接重画全书或刷新所有通过结论。
- 默认选材依赖文件名和时间，打包前必须人工核对 `--inspect`；以后可按实际需要增加显式选材入口。
- 结构校验不能识别人物身份、手指或剧情语义。严格保留内部实际看图和试听。
- 旧内容兼容不代表符合全部新制作标准。已有书籍只在明确指定后返修、迁移或重新上架。
