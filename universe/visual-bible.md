# 视觉设定基础

角色参考以最新已批准的 `universe/character-registry.md` 和网页角色图鉴为准。在原有分镜、插图和审核步骤中使用以下补充规则，避免逐页独立起稿。默认只用于后续新绘本；已有绘本及候选等用户明确指定后再修改，不自动更新。

## 默认画面语言

- 儿童绘本插画，圆润而清晰的形状，纸张与彩铅混合质感。
- 暖色主体配低饱和自然背景，夜景保持柔和而非漆黑。
- 角色表情清楚，动作轮廓容易被四岁儿童辨认。
- 每页一个视觉焦点，背景细节服务于寻找、预测或情绪表达。
- 不在生成图中排长篇文字；正文由后续排版添加。
- 正文插图母版采用全画幅场景：环境、地面或天空自然延伸到四边，不在底部或其他位置生成浅色横条、空白文字区、边框、卡片、横幅或占位框。
- “无文字”只表示图片内不生成字，不表示要为文字预留空白。播放器和 PDF 的正文属于独立排版层，不得重复占用母版画面面积。
- 如果某个纸质版式确实需要图文同页，先保留全画幅母版，再由排版程序生成带文字的派生版；不得把排字需要反向写进母版插图提示词。

## 连续性规则

- 每个角色建立正面、侧面、常用表情、设定身高、尺寸比例和固定颜色。
- 角色设定图必须为每个角色/形态锁定固定的手指、脚趾或爪趾数量；同一张设定图的正面、三分之四、侧面和表情视图必须保持数量一致。生成后逐视图检查，发现数量漂移先返修设定图再用于图鉴或故事。
- 设定身高是新故事确定视觉比例时的起始参考，不是要求所有故事使用完全相同的像素高度比。
- 每本故事在 Gate C 选定一张代表性合格页作为“故事尺度锚点”，记录同框角色的相对大小；同一本故事后续页面在近似景深和姿态下必须尽量保持该关系。
- 透视、坐姿、弯腰、跳跃或明确剧情可以造成暂时视觉高度变化，但应能从画面解释，不能出现无原因的逐页忽大忽小。
- 不同故事可以因构图、镜头语言和整体风格采用适度不同的角色相对尺度；跨故事尺度只作参考，不作为硬性拒绝门禁。
- 直接在原有 `storyboard.json` 的 `visual_production` 中统一记录画风、角色图、服装、故事不变事实、尺度和各场景布局；每个 `shots[]` 记录本页场景、角色、状态和允许变化，与既有动作、镜头、情绪、安全限制一起维护，不另建独立视觉计划。
- 每页提示词从同一份分镜生成，重复角色的不变特征，而不是只引用角色名字；先消除“蓝短袖”和笼统“睡衣”等冲突描述，剧情换装则明确发生页及前后状态。
- 生成时实际附带角色图和本场景合格参考，不能只在提示词里写路径。身份由角色图确定，布局由本场景参考确定，跨地点的尺度参考只提供比例和画风，不能带入原背景。
- 使用家长批准的参考图时，只改变场景、姿势和明确要求的服饰。
- 每个重复场地在批量生图前建立“场景锚点”：固定空间结构、道路或房间朝向、地标位置、门窗与家具位置、长期道具、主视轴和基础色光。
- 故事明确仍在同一地点时，后续页面必须引用首张合格场景锚点；只改变角色动作、镜头远近和剧情明确改变的物件状态，不得随机重排建筑、树木、道路、窗户、桌椅或固定道具。
- 时间、天气、开关状态、收纳进度或物件损坏等变化，只有在正文或分镜明确要求时才改变，并在视觉审核中逐项记录前后状态。
- 剧情确实换场时，应建立新的场景锚点，并说明从旧场景到新场景的转换。不是整本书固定一个场景，也不固定剧情明确改变的事物；同地昼夜、换床品、移动家具等按故事记录变化。
- 在原有代表页检查中先确认场景与尺度，再制作同场景后续页。后续始终引用固定合格参考，前页仅补充状态，不串联一串未经检查的图片。
- 每页保持一个主要动作；抱持、交叉肢体和反向镜头容易出错时，先简化构图或设计空间关系，避免连续重复生图。
- 生成后逐页检查脸部、肢体、颜色、故事内尺寸关系和多余角色；尺寸比较以本故事尺度锚点为主，不机械套用其他故事。
- 生成后查看整本联系表，仅对疑点页放大原图检查构图；不重复理解未变化图片。画面下方约四分之一必须有与场景一致的有效内容，不能出现均匀浅色底栏或突然消失的地面纹理。

## 图文收敛与迭代预算

- 生图前先锁定不可迁就画面的故事事实：主旨、因果关系、角色关键选择、安全边界、跨页伏笔与回收、必须出现的关键动作或物件。
- 每页先生成一个初稿；整本只做一次联系表批量理解，随后只对联系表标出的页面查看原尺寸。图片文件未变化时复用既有审核结论，不重复理解。
- 图像没有身份错误、异常肢体、危险动作、随机文字、底栏或连续性硬伤，只是非关键动作、道具数量、表情或环境细节与原文略有差异时，可以优先小幅修改儿童文本来适配好图。
- 文本适配必须同时更新 `story.json`、`story.md`、`narration.json`、`storyboard.json` 和 `review.md`，并只重做受影响页面的音频。不得改变主旨、因果、已确认角色事实、安全要求或跨页逻辑。
- 默认每页最多在初稿后做一次定向返修。只有第一次返修明确改善了单一硬伤、剩余问题也可精确描述时才允许第二次；否则重新设计构图或暂停该页，不连续生成近似版本。
- 每页在视觉审核中记录 `accept`、`text-adapt` 或 `repair`，并写明理由、所用图片版本以及是否触发了文本和音频更新。

## 正文插图提示词固定约束

每一页提示词都应包含等价约束：

> 4:3 横版全画幅场景，画面自然延伸到四边；无文字、无标题、无边框、无横幅、无底部留白、无字幕区、无排版占位。

提示词中不得再出现“底部留白”“正文区”“排字区”“浅色安静区域”或“约 22% 留白”等要求。需要低细节背景时，应把它设计成场景内的天空、墙面、草地或水面，并保持与画面连续，不能形成独立色带。

## 原有分镜与审核的工具补充

`templates/storyboard.schema.json` 已扩展，`shots` 固定为 6 页（1–6），封面单独使用 page 0：

- `visual_production`：`style`、`story_invariants`、`scale_relationship`、`scale_anchor_page`、`scale_anchor`、`characters` 和 `scenes`。
- `characters` 按角色 ID 存放 `invariants`、`costume` 和 `reference`；角色批准状态仍核对图鉴，不由程序推断。
- `scenes` 按地点/场景状态 ID 存放 `layout`、`anchor_page` 和 `anchor`。尚未画出的首张参考可为 null；后续页必须使用已经看图确认的参考。
- `shots[]` 在既有 `page`、`composition`、`action`、`mood`、`prompt`、`negative_constraints` 上补充 `scene`、`characters`、`state`、`allowed_changes`。`cover` 使用同样结构，页码为 0。
- 参考图结构为 `path`（工作区相对路径）、`sha256`（实际文件摘要）、`reviewed`（实际内部看图确认）；不可用占位值冒充。

在原有生图步骤调用下面的辅助命令，产物是从分镜派生的提示词和参考清单，不需要家长维护或选择另一套流程：

```powershell
python scripts/visual_plan.py drafts/<story>/storyboard.json --page 1 --output drafts/<story>/production/page-01-input-v1.json
python scripts/visual_plan.py drafts/<story>/storyboard.json --review drafts/<story>/visual-review.json
python scripts/prepare-review-candidate.py <story> --revision-prefix <new-revision> --inspect
python scripts/prepare-review-candidate.py <story> --revision-prefix <same-new-revision>
```

编译结果同步回该页原有 `prompt`，然后实际附带参考图生成。编译时忽略旧的派生 `prompt`，避免把它作为另一份权威输入；情绪和安全约束仍保留。输出不覆盖旧文件。当前工具不提供种子、参考权重或遮罩参数，不编造这些控制。

原有 `review.md` 继续记录图文判断；`visual-review.json` 是对应的结构化证据，包含封面与全部内页：`page`、`input_digest`、`image`、`image_sha256`、`verdict`、`reason`、`reviewer`、`attempts`。文本适配需 `text_audio_synced`，第三次生成需 `second_repair_reason`。参考/输入变化后先核对受影响关系，再更新记录，不自动重画未受影响的图片。当前摘要保守绑定整份计划，变更后需要确认记录，不等于全书画面失败。

原有打包步骤的 `--inspect` 只输出选中素材和摘要。基于实际检查填写 `internal-review.json`：`package_digest`、`result`、`reviewer`、`reviewed_at`、`checks`。每项包含 `id`、`status`、`evidence`；检查涵盖 `content`、`audible_speakers`、`character`、`scene`、`full_bleed`、`contact_sheet`、`audio`、`cover_title`、`page_timeline`。最终打包核验这些记录并生成原有 `ai-review.json`，不能自动制造通过结论，也不增加家长中间审核步骤。

程序只验证引用和记录，不判断脸像不像、肢体是否正常、布局是否真的连续。下一本新书在既有 `review.md` 中记录首轮通过页数、返修次数、缺陷类型和耗时，用整本看图验收判断效果，不预先宣称提升比例。

## 具体作品再决定

- 打印纸张和版式等作品要求在用户提出时确定。
- 角色外观直接沿用最新已批准图鉴，不重新要求确认已批准设定。
