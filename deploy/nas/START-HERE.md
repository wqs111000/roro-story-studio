# NAS 绘本展示版准备包

这个包只包含电脑书架当前可见的最终版本和当前角色图鉴：

- 不含草稿、待审核内容、已下架绘本和制作队列；
- 每本书只有 `current.json` 指向的一个发布版本，不含历史版本；
- 含最终版本所绑定的封面、页面、文字、全部可选音轨和同步文件；
- 含当前图鉴实际引用的角色设定图；
- 含纯运行环境镜像、外置网页代码和空的 PDF 缓存目录，不含旧 PDF 缓存、审核 PIN、日志、分享记录或家庭参考照片。

镜像只包含 Python、字体和 PDF 依赖；网页及服务代码位于 `app/service` 和 `app/scripts`，以只读方式挂载。
以后仅修改代码时，更新这两个目录并重启容器即可，不需要重新导入镜像。
容器根文件系统保持可写，以兼容绿联 Docker 对嵌套挂载点的创建；代码、绘本和服务数据挂载仍是只读的。
只有 Python、字体或 `requirements-service.txt` 依赖变化时才需要更新 `image.tar`。

NAS 服务使用 `--display-only`：开放书架、播放、图鉴和下载；隐藏工作台和分享按钮，
工作台接口与所有写入请求被拒绝。制作、审核、上下架继续在电脑完成，之后重新生成展示包更新 NAS。

## 在绿联 Docker 界面部署

1. 如果 NAS 上已经存在并正在使用 `roro-story-runtime:py312-reportlab4-v1`，
   本次不需要导入 `image.tar`。它只包含 Python、字体和 PDF 依赖，不包含网页代码、绘本或同步数据。
   只有运行环境依赖变化，或 NAS 上没有这个镜像时，才导入 `image.tar`。
2. 左侧打开“项目”并创建：
   - 项目名称：`roro-story-studio`
   - 存放路径：使用本准备包实际所在目录，即 `preparation.json` 中的 `linux_path`（默认位于 `staging/<版本>/`）
   - Compose 配置：点击“导入”，选择本包的 `compose.yaml`；相对挂载路径必须以本包目录为基准
   - 环境变量从本包 `.env` 导入，核对 `PUID`、`PGID` 和 `RORO_LISTEN_ADDRESS`；监听地址必须是 NAS 实际拥有的地址
3. 勾选“创建完成后立即运行”，点击“立即部署”。

代码更新后，在“项目”页重启 `roro-story-studio` 项目即可。无需再次导入镜像。

访问部署者配置的 NAS 地址（例如 `http://<NAS_HOST>:8877`），逐项测试书架、全部声音、自动翻页、iPad 显示、
图鉴和 PDF 下载。当前包还未启动。
